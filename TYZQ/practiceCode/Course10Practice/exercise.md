# Course10Practice：实验室设备监测系统

> 题面由 Codex（GPT-6）根据当前仓库的课程笔记与练习设计，日期：2026-11-10。本文是练习说明，不包含完整实现；尚未经学习者确认。

编写一个命令行程序 **Lab Device Monitor（LDM）**，管理实验室中的多台设备，记录它们的采样值，并通过一个整数中的不同 bit 保存设备状态。

本题承接 Course8 的采样统计与回调排序、Course9 的结构体和多文件组织，重点练习 Lecture10 的**返回结构体、结构体指针、`const`、位掩码和位移**。

使用固定容量数组，数据只保存在内存中。完成必做功能即可；动态内存、链表、文件读写不属于本题要求。

## 1. 具体要实现的功能

### 1.1 菜单与容量

程序循环显示以下菜单，选择 `0` 或遇到 EOF 时正常退出。

```text
========== Lab Device Monitor ==========
1. Register device
2. Display all devices
3. Change device state
4. Add reading
5. View device report
6. Filter devices by flags
7. Sort devices
0. Exit
========================================
```

统一约定：

| 项目 | 要求 |
| --- | --- |
| 设备数量 | 最多 10 台 |
| 设备 ID | 正整数，不可重复；不要求连续 |
| 设备名称 | 最多 23 字节，另留 1 字节给 `\0`；允许内部空格，必须含非空白字符 |
| 每台设备的采样容量 | 最多 10 个整数 |
| 合法采样范围 | `0～100`，两端包含 |
| 正常采样范围 | `10～90`，两端包含 |
| 报警采样范围 | `0～9` 或 `91～100` |

名称可以重复。为方便初期测试，先使用英文名称；字节数不等于中文字符数。

### 1.2 注册设备

输入 ID 和名称，验证通过后添加一台设备。

- 注册前检查容量，拒绝重复 ID、非正数 ID 和不合要求的名称。
- 新设备初始状态为“在线、非维护、无报警、无数据”。
- 初始采样数量为 0。
- 注册失败时，已有设备及设备总数保持原样。
- 所有字段输入成功并通过验证后，再把完整记录加入设备数组。

### 1.3 使用位标志保存状态

每台设备只使用一个 `unsigned int flags` 保存以下四种状态，禁止再用四个独立变量重复保存它们。

| 位编号 | 标志名 | 掩码值 | 为 1 时的含义 | 更新来源 |
| --- | --- | --- | --- | --- |
| bit 0 | `ONLINE` | 1 | 设备在线 | 手动切换 |
| bit 1 | `MAINTENANCE` | 2 | 设备处于维护模式 | 手动开启或关闭 |
| bit 2 | `ALARM` | 4 | 最近一次成功录入的采样触发报警 | 录入采样时自动更新 |
| bit 3 | `HAS_DATA` | 8 | 已有至少一个采样 | 首次成功录入时自动设置 |

bit 0 是最右侧的最低位。其余位保持为 0；上述掩码要求用无符号整数左移表达式定义。

“修改状态”先按 ID 找到设备，再提供三种操作：

1. 切换在线／离线：使用 XOR 翻转 `ONLINE`。
2. 开启维护：使用 OR 设置 `MAINTENANCE`。
3. 关闭维护：使用 AND 配合 NOT 清除 `MAINTENANCE`。

开启维护和关闭维护都应允许重复执行，重复执行不会反向切换状态。每次只改变目标位，保留其他位。

在线状态和维护状态彼此独立：设备可以同时在线且处于维护模式。切换状态不会清空历史数据，也不会自动清除报警。用户不能直接修改 `ALARM` 或 `HAS_DATA`。

### 1.4 录入采样

按设备 ID 录入一个整数采样值，必须同时满足：

- 设备存在，且在线。
- 设备不处于维护模式。
- 采样数组尚未满。
- 数值在 `0～100` 内。

成功后，将数据追加到有效采样的末尾，增加采样数量，并更新 `HAS_DATA` 和 `ALARM`。

**报警只反映最近一次成功录入的采样。** 例如先录入 95，再录入 50，应保留两条数据，但清除报警。录入失败时，采样数组、采样数量和所有状态位均保持原样。

数组满后拒绝继续录入，不覆盖最早的数据。样本按录入顺序保存。

### 1.5 显示设备与统计报告

“显示所有设备”至少显示：ID、名称、采样数量、四个状态的文字含义，以及状态整数的低 8 位二进制表示。

二进制输出必须通过循环、位移和掩码生成，从 bit 7 打印到 bit 0，不硬编码全部状态组合。例如：

```text
ID: 101
Name: Sensor A
Readings: 2
State: ONLINE | MAINTENANCE_OFF | ALARM_OFF | HAS_DATA
Flags: 00001001
```

这里 `MAINTENANCE_OFF` 和 `ALARM_OFF` 分别表示维护位和报警位为 0，具体排版自行设计。

“查看设备报告”按 ID 查找并显示：

- 设备基本信息和当前状态。
- 按录入顺序排列的全部有效采样。
- 有效采样数量、总和、平均值、最小值、最大值。

**统计函数必须返回一个包含这些结果的结构体。** 与 Course9 的多个输出指针作对照，练习另一种返回多个计算结果的方式。

无数据时，返回结果中的数量、总和、平均值、最小值和最大值均初始化为 0；界面显示 `No readings`，平均值和极值显示 `N/A`，不能将占位的 0 解释成实际统计结果。统计包含该设备全部历史采样，不受当前在线或维护状态影响。

### 1.6 按状态筛选

输入一个十进制掩码 `1～15`，再选择以下一种匹配模式：

- **ANY**：设备拥有掩码中至少一个状态。
- **ALL**：设备拥有掩码中的全部状态。

例如掩码 5 表示选择 `ONLINE` 和 `ALARM`：

- ANY：在线或报警的设备都会显示。
- ALL：只显示既在线又报警的设备。

这里筛选的是“哪些位为 1”；不要求实现“必须离线”等对 0 位的筛选。掩码 0、负数和大于 15 的值均拒绝；无匹配结果时给出提示。筛选不得修改设备数据。

### 1.7 使用回调排序

用同一个排序函数配合不同的比较回调，支持：

1. 按设备 ID 升序。
2. 按平均采样值降序。

平均值相同时，按 ID 升序；无采样的设备统一排在有采样的设备之后，无采样设备之间按 ID 升序。

沿用 Course8 的 `shouldSwap` 思路：回调接收两台只读设备，返回非零表示“左边应该排在右边之后”。算法可选冒泡排序或选择排序，不要求学习 `qsort`。

排序直接调整设备数组的有效部分，并显示结果。交换时必须交换完整设备记录；一台设备的 ID、名称、样本和状态不能被拆散。不要改变任何设备内部的采样顺序。

## 3. 注意事项与验收

### 3.1 容易出错的地方

- **容量不等于有效数量。** 设备遍历到设备数，采样遍历到采样数，不遍历全部未使用槽位。
- **ID 不等于下标。** 排序后同一设备的下标可能改变；每次按 ID 操作时重新查找，避免缓存旧下标或指向旧槽位的指针。
- **修改原设备需要地址。** 按值接收整个结构体只得到副本；显示、查找、统计和比较函数使用 `const` 表达只读意图。
- **先检查，后写入。** 条件全部通过后再追加数据、更新数量及状态；不要先修改再发现失败。
- **状态位有明确来源。** 始终保持 `HAS_DATA` 与采样数量一致；报警由最后一次成功采样决定，不由平均值或历史最大值决定。
- **设置、清除、翻转不是同一件事。** 开启维护应当可重复；不能用 XOR 实现“始终开启”，也不能通过把整个 `flags` 赋值为某个单独掩码来设置一位。
- **位运算和逻辑运算要分清。** ANY 和 ALL 的判断不同；与相等比较混合时用括号明确位运算的计算顺序。
- **位编号和掩码值要分清。** bit 2 对应掩码值 4。使用 `1u` 构造掩码，位移量保持在有效范围内。
- **二进制显示需要固定输出 8 位。** 注意倒序循环的结束条件，防止无符号循环变量减到 0 后继续回绕。
- **平均值需要浮点除法。** 仅将整数除法结果赋给 `double` 不能补回已丢失的小数；空数据不做除法，也不读取第一个样本。
- **报警值也是合法数据。** 95 应当被保存并触发报警；101 应当被拒绝。两个概念不能混淆。
- **字符串保留终止符空间。** 可复用 Course9 的 `readInt` / `readString`；名称不能为空白等业务限制需要另外验证。
- **输入失败应可恢复。** `abc`、`12abc`、超长行和整数溢出不能导致死循环或污染下一次输入；EOF 正常结束，不提交正在录入的半条记录。
- **按 C11 编译。** 建议开启 `-Wall -Wextra -Wpedantic`；不依赖 `0b...` 字面量或 `%b` 输出二进制。若另写测试入口，分别构建 `main.c` 和 `test.c`，不要把两个 `main` 链接在一起。

### 3.2 核心状态验收

按以下顺序对同一台新设备操作，预期结果如下。二进制字符串均按 bit 7 到 bit 0 排列。

| 操作 | 预期 flags | 预期采样数 | 说明 |
| --- | --- | --- | --- |
| 注册设备 | `00000001` | 0 | 在线，无数据 |
| 录入 95 | `00001101` | 1 | 在线、报警、有数据 |
| 录入 50 | `00001001` | 2 | 清除报警，保留历史数据 |
| 开启维护 | `00001011` | 2 | 仅维护位改变 |
| 再次开启维护 | `00001011` | 2 | 保持开启 |
| 维护中录入 20 | `00001011` | 2 | 拒绝录入，全部数据保持原样 |
| 关闭维护 | `00001001` | 2 | 仅维护位改变 |
| 切换为离线 | `00001000` | 2 | 数据仍保留 |
| 离线时录入 20 | `00001000` | 2 | 拒绝录入 |
| 切换为在线 | `00001001` | 2 | 恢复在线 |
| 录入 101 | `00001001` | 2 | 拒绝越界数值 |

这一轮最终报告：采样为 `95, 50`，总和 `145`，平均值 `72.50`，最小值 `50`，最大值 `95`，当前无报警。

### 3.3 其他验收场景

| 场景 | 验收重点 |
| --- | --- |
| 空设备表上显示、筛选、排序 | 合理提示，不访问越界 |
| 按不存在的 ID 操作 | 提示未找到，不修改其他设备 |
| 重复 ID；第 11 台设备 | 拒绝添加，设备总数不变 |
| 新设备直接查看报告 | 无数据提示，不除以 0、不读取无效样本 |
| 在线且非维护时，依次录入 9、10、90、91 | 报警状态依次为开、关、关、开 |
| 在线且非维护时，录入 0、100、-1 | 前两个成功且报警，最后一个拒绝 |
| 第 11 个采样 | 拒绝，不覆盖原有样本，不改变报警位 |
| 仅在线设备、离线但报警设备、在线且报警设备，以掩码 5 筛选 | ANY 匹配三者，ALL 只匹配第三者 |
| 两台有数据设备的平均值相同 | 按 ID 升序；平均值为 0 的有数据设备仍排在无数据设备前 |
| 排序后按 ID 查看报告 | 名称、状态和全部采样仍属于原设备，采样顺序不变 |
| 非法输入、超长输入、EOF | 能重试或正常退出，不提交半条记录 |
