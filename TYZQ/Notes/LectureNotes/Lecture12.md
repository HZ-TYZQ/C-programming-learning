# Part 1｜Linked List 链表回顾

## 1.1 基本概念

链表（Linked List）是一种由 **节点（node）** 组成的动态数据结构。节点通常包含：

- **Data**：存储的数据。
- **Reference**：指向下一个节点的指针。

单向链表示意：

```text
head
 ↓
[Data | next] -> [Data | next] -> [Data | NULL]
```

**头节点（head node）** 是访问链表的重要入口；头节点是否实际存放业务数据，取决于实现（有些实现有哨兵节点）。课件特别提醒：不能随意丢失或覆盖指向链表开头的指针，否则可能失去访问后续节点的途径（课件称为 *zombie nodes*）。

## 1.2 主要操作与时间复杂度

| 操作 | 链表特点 | 常见时间复杂度 |
|---|---|---|
| 线性查找（Linear Search） | 从头开始沿指针逐节点查找 | **O(N)** |
| 在已知节点之后插入 | 修改少量指针即可 | **O(1)** |
| 先查找目标，再插入或删除 | 定位节点需要遍历 | 通常 **O(N)** |
| 在有序链表上二分查找 | 无法像数组那样直接定位中间元素 | 课件：**O(N)** |

> [!important] 链表的“二分查找”为什么不是 O(log N)？
> 数组可以通过 `a[mid]` 直接访问中间位置，链表必须**顺着 `next` 一步步走到中间节点**。因此，虽然比较次数可能减少，寻找中间节点仍需要遍历成本。

## 1.3 链表 vs 数组

| 对比 | 数组 Array | 链表 Linked List |
|---|---|---|
| 随机访问 | 支持 `a[i]`，**O(1)** | 需要遍历，通常 **O(N)** |
| 插入 | 中间插入常需移动元素 | 找到插入位置后改指针很快 |
| 内存布局 | 元素连续 | 节点可以分散存储 |
| 大小变化 | 固定大小数组不便扩容 | 可以动态增减节点 |
| 额外开销 | 可能存在未使用的容量 | 节点指针和分配管理需要额外空间 |

> [!note] 课件与实际实现
> 课件强调链表可动态改变大小、避免固定容量浪费；实际程序里仍有**每个节点的指针和动态内存分配开销**，不是绝对“零浪费”。

## 1.4 三种链表

```text
Singly linked list（单向链表）
head -> A -> B -> C -> NULL

Circular linked list（循环链表）
head -> A -> B -> C ─┐
        ^            │
        └────────────┘

Doubly linked list（双向链表）
NULL <- A <-> B <-> C -> NULL
        ^           ^
       head        tail
```

- **单向**：只能沿 `next` 向前遍历，尾节点指向 `NULL`。
- **循环**：尾节点重新连接到首节点；遍历不能只以 `NULL` 为结束条件。
- **双向**：存在前驱、后继关系，可以向前和向后遍历；课件以 `head` 和 `tail` 为两个入口。

# Part 2｜File I/O 文件输入输出

## 2.1 流（stream）是什么？

C 标准库将输入、输出抽象为**流**：程序面对的是一个可读或可写的数据序列，而不必每次直接管理硬盘。

```text
输入来源（键盘 / 文件 / ...）
              ↓
            Stream
              ↓
           C 程序
              ↓
            Stream
              ↓
输出目的地（终端 / 文件 / ...）
```

`<stdio.h>` 提供三个预先打开的标准流：

| 标准流 | 用途 |
|---|---|
| `stdin` | 标准输入；例如 `getchar()`、`scanf()` |
| `stdout` | 标准输出；例如 `putchar()`、`printf()` |
| `stderr` | 标准错误输出；用于诊断信息 |

> [!tip] 从以前的 `safe input` 连接到文件 I/O
> 你在 `Course9Practice` 中用过 `fgets(buffer, sizeof(buffer), stdin)`。现在读取磁盘文件时，只要把输入流换成打开的文件流，就可以继续使用 `fgets(buffer, sizeof(buffer), fp)`。

## 2.2 什么是 `FILE *`？

```c
FILE *fp;
```

- `FILE` 是标准 I/O 库使用的**文件流管理对象类型**。
- `fp` 是指向这种对象的**指针**，**不是直接指向硬盘上的文件字节**。
- 文件流内部维护与读取位置、缓冲和状态有关的信息；我们通过标准库函数操作它。

> [!important] 指针 ≠ 读取位置
> 读完一个字符后，`FILE *fp` 这个指针变量的值通常**不变**；改变的是它所指向的**流的当前位置/状态**。

## 2.3 `fopen()`：打开文件

```c
FILE *fopen(const char *filename, const char *mode);
```

最基本的三个模式（**课件重点**）：

| 模式 | 可读 | 可写 | 文件存在时 | 文件不存在时 |
|---|---|---|---|---|
| `"r"` | ✓ | × | 保留文件，从头读取 | 打开失败 |
| `"w"` | × | ✓ | **打开成功时立即清空** | 创建新文件 |
| `"a"` | × | ✓ | 保留原内容，**追加到末尾** | 创建新文件 |

**一定检查是否打开成功：**

```c
FILE *fp = fopen("data.txt", "r");
if (fp == NULL) {
    perror("fopen");
    return 1;
}
```

> [!warning] `"w"` 的截断行为
> **只要 `fopen("data.txt", "w")` 成功，原内容就会被截断为 0 字节**，即使紧接着 `fclose(fp)`、完全没有写入数据也是如此。

**课外补充／学习讨论：带 `+` 的读写模式**

| 模式 | 可读 | 可写 | 打开时的效果 |
|---|---|---|---|
| `"r+"` | ✓ | ✓ | 文件必须存在，保留内容 |
| `"w+"` | ✓ | ✓ | 创建或清空文件 |
| `"a+"` | ✓ | ✓ | 保留内容，写入始终追加到末尾 |

例如：文件原本是 `Hello`，以 `"r+"` 打开后，直接写入 `"XY"`：

```c
FILE *fp = fopen("data.txt", "r+");
if (fp != NULL) {
    fprintf(fp, "XY");
    fclose(fp);
}
```

最终是 `XYllo`，**不是** `XYHello`，因为从开头位置**覆盖**了两个字符。

> [!warning] 读写模式的进一步注意事项
> 在 `r+ / w+ / a+` 更新流中，**读操作和写操作不能毫无条件地随意交替**；切换方向时通常需要定位操作（例如 `fseek()`），或者满足标准库允许的特殊条件。这是学习讨论中的延伸知识，Lecture 12 未展开具体规则。

### 文件路径（学习讨论）

`fopen("data.txt", "r")` 使用的相对路径通常相对于**程序运行时的当前工作目录**（current working directory），不一定是 `.c` 源文件所在目录。

- `"data.txt"` 与 `"./data.txt"`：通常表示当前工作目录内同一个文件。
- `"../data.txt"`：表示上一级目录的文件。
- 绝对路径：从文件系统根目录开始定位。

## 2.4 `fclose()`：关闭文件

```c
int fclose(FILE *stream);
```

- 成功时返回 `0`，失败时返回 `EOF`。
- 关闭并释放与该流相关的资源。
- 会尝试把尚未写出的输出缓冲数据写出去；**写出可能失败**，所以重要程序也应检查返回值。
- 关闭后不要继续使用原来的 `FILE *` 进行 I/O。

```c
if (fclose(fp) == EOF) {
    perror("fclose");
}
```

## 2.5 `fflush()`：刷新输出缓冲区

```c
int fflush(FILE *stream);
```

作用：将 C 标准 I/O 库中待输出的数据尝试交给底层系统，**不关闭文件流**。成功时返回 `0`，失败时返回 `EOF`。

```c
fprintf(fp, "Hello");
fflush(fp);  // 尝试刷新输出缓冲；流继续保持打开
```

> [!important] 缓冲区 ≠ 已经永久保存到硬盘
> **课外补充／学习讨论**：`fflush()` 清的是 C 标准库的输出缓冲，但操作系统还可能使用 Page Cache 等机制；刷新到系统不等于已经完成断电安全的持久化。程序崩溃、系统崩溃、断电不是同一层级的问题。Lecture 12 只强调缓冲与程序崩溃导致数据丢失的风险。

# Part 3｜从文件读取

## 3.1 `fgetc()`：一次读取一个字符

```c
int fgetc(FILE *stream);
```

- 成功：返回读到的字符值，类型是 **`int`**。
- 到达文件末尾**或发生读取错误**：返回 `EOF`。
- 每次读取成功，流的读取位置向前推进。

```c
int ch;
while ((ch = fgetc(fp)) != EOF) {
    putchar(ch);
}
```

> [!warning] 一定用 `int ch` 接收
> 因为返回值还需要表示特殊的 `EOF`，不能依赖 `char` 保留该特殊值。

`getchar()` 可以理解为从标准输入流读取的版本，即功能上等价于 `fgetc(stdin)`。

### 为什么 `while` 条件要加括号？

```c
(ch = fgetc(fp)) != EOF
```

- **先赋值**：`ch = fgetc(fp)`。
- **再比较**：`ch != EOF`。

如果写成：

```c
ch = fgetc(fp) != EOF;
```

由于 `!=` 的优先级高于 `=`，`ch` 得到的是比较结果 `0/1`，而不是原字符。

### 读取次数与循环次数

文件只有 `X`，没有额外换行符：

| 第几次调用 `fgetc` | 返回值 | 是否进入循环体 |
|---|---|---|
| 1 | `'X'` | 是 |
| 2 | `EOF` | 否 |

因此 `fgetc()` **调用 2 次**，`putchar()` **只调用 1 次**。

## 3.2 `fgets()`：读取一段文本（常用于读一行）

```c
char *fgets(char *str, int n, FILE *stream);
```

成功读取时，最多读入 **`n - 1` 个字符**，并在末尾自动加上 `\0`；通常遇到换行符 `\n` 会停止，而且**会保留读到的 `\n`**。

- 成功：返回 `str`。
- 还没读到任何字符就遇到文件末尾，或遇到读取错误：返回 `NULL`。

```c
char str[100];
if (fgets(str, sizeof(str), fp) != NULL) {
    printf("%s", str);
}
```

> [!important] 一次 `fgets()` 不保证读完整行
> 停止条件：**读到换行符**、**达到 `n-1` 个字符上限**，或者**遇到文件末尾**。

### 实际推导：缓冲区小于一行

文件为 `Hello\nWorld`，数组长度为 4：

```c
char str[4];
```

| 连续调用次数 | 当前读到的字符 | `str` 表示的 C 字符串 |
|---|---|---|
| 第一次 | `Hel` | `"Hel"` |
| 第二次 | `lo\n` | `"lo\n"` |
| 第三次 | `Wor` | `"Wor"` |
| 第四次 | `ld` | `"ld"` |

第四次读取后，`str[0]='l'`、`str[1]='d'`、`str[2]='\0'`，而 `str[3]` **不会因为本次 `fgets()` 自动清零**。若沿用第三次结果，`str[3]` 刚好仍是之前的 `\0`。

**重要结论：** `fgets()` 只保证成功读取的字符串有结尾 `\0`，并不负责清空整个字符数组。

### 与 `fgetc()` 的联系

```c
int ch;
while ((ch = fgetc(fp)) != EOF && ch != '\n') {
    putchar(ch);
}
```

也能逐个字符处理一行，但它**没有自动把一整行保存到数组中**，并且这里的循环会消费却不输出换行符；这和 `fgets()` 的行为不同。

## 3.3 `fscanf()`：按格式读取

```c
int fscanf(FILE *stream, const char *format, ...);
```

与 `scanf()` 的核心解析规则相同，只是指定的输入流不同：

```c
scanf("%d", &num);       // 标准输入（stdin）
fscanf(fp, "%d", &num);  // 指定文件流
```

### 返回值：成功完成赋值的项目数

```c
int a, b;
int result = fscanf(fp, "%d %d", &a, &b);
```

| 本次读取情况 | `result` |
|---|---|
| 两个整数均成功解析并赋值 | `2` |
| 第一个整数成功，第二个失败 | `1` |
| 第一个整数就遇到无效非数字字符 | `0` |
| 尚未成功赋值就遇到输入结束（或相应输入失败） | `EOF` |

> [!warning] 只成功读取一部分时，部分变量会被改写
> 例如输入是 `103 hello`，`fscanf(fp, "%d %d", &id, &score)` 返回 `1`，`id` 已经变成 `103`，而 `score` 没有由这次调用赋新值。不要在返回值不符合预期时直接使用这些变量。

> [!tip] `EOF` 与 `1` 的区分
> 若文件最后只有 `103`，第一个 `%d` 已经成功赋值，第二个 `%d` 才遇到末尾，则本次调用返回 **`1`**，不是 `EOF`。

### 不同格式说明符对读取位置的影响

| 格式 | 是否跳过输入前导空白 | 读取效果 |
|---|---|---|
| `%d` | 是 | 读取整数，停在不能继续属于整数的字符前 |
| `%f` | 是 | 读取 `float` 浮点数 |
| `%lf` | 是 | 读取 `double` 浮点数 |
| `%s` | 是 | 读取一段非空白文本；使用时必须限制宽度，防止数组越界 |
| `%c` | **否** | 直接读取字符，包括空格、`	`、`
` |
| 格式字符串中的空白（如 `" %c"`） | 是 | 消耗**连续的**输入空白，直到下一个非空白字符或输入结束 |

**练习过的例子：**

```text
文件：␣␣␣A␣B   （␣ 表示一个空格）
```

```c
char a, b;
fscanf(fp, " %c%c", &a, &b);
// a == 'A'
// b == ' '   ← 第二个 %c 没有跳过空格
```

改成：

```c
fscanf(fp, " %c %c", &a, &b);
// a == 'A'
// b == 'B'
```

### 文件流位置由读取操作共享

对于文件：

```text
10 20 30
```

```c
int a, b, c;
fscanf(fp, "%d", &a);     // a = 10
fscanf(fp, "%d %d", &b, &c); // b = 20, c = 30
```

并不是每个 `fscanf()` 从文件开头重新读，而是**从该流当前的位置继续**。

### 课外补充／学习讨论：错误输入如何跳过？

假设数据里有：

```text
101 90
102 85
hello 50 60
103 95
```

遇到 `hello` 时，第一个 `%d` 解析失败；重复尝试同样的 `%d`，可能一直卡在字符 `'h'`。

- 若**一整行是一条记录**：可以用 `fgetc()` 消耗到行末，再尝试下一行。
- 若**空白分隔的每一项是独立数据**：可以考虑 `%*s` 跳过**一个**非空白文本字段（`*` 表示抑制赋值），而不是整行。

```c
// 仅作“跳过一个非空白字段”的示意
fscanf(fp, "%*s");
```

> [!caution] 错误恢复要先定义“记录”
> 丢掉整行还是丢掉一个字段，没有通用唯一答案；取决于文件格式。如果字段之间有依赖关系，随意跳一个字段可能导致数据错位。写健壮程序还应检查跳过操作是否真的取得进展。

## 3.4 `feof()`：为什么不能用于预判读取成功？

```c
int feof(FILE *stream);
```

`feof(fp)` 检查**文件结束标志是否已经被设置**：

- 未设置：返回 `0`。
- 已设置：返回**非零值**（不保证刚好是 `1`）。

> [!important] 关键区别
> **“已经读完最后一个有效字符”不等于“文件结束标志已经设置”。** 一般要再尝试一次读取，真正遇到末尾，结束标志才会被设置。

### 错误示范：先看 `feof` 再读

```c
while (!feof(fp)) {
    int ch = fgetc(fp);
    printf("%c", ch);   // 可能把 EOF 错当成字符输出
}
```

文件只含 `X` 时：

| 次数 | 循环条件检查 | `fgetc` 结果 |
|---|---|---|
| 第一次 | `feof == 0` | `'X'` |
| 第二次 | `feof == 0` | `EOF` |
| 第三次检查 | `feof != 0` | 不再进入循环 |

**正确思路：先读取，再根据成功与否决定是否处理。**

```c
int ch;
while ((ch = fgetc(fp)) != EOF) {
    putchar(ch);
}
```

> [!note] EOF 不一定只代表“正常读到末尾”
> `fgetc()` 返回 `EOF` 也可能是读取错误。需要进一步区分时，可使用 `feof(fp)` / `ferror(fp)` 查询流状态（`ferror` 为学习讨论延伸，非课件 I/O 总结表重点）。

# Part 4｜向文件写入

## 4.1 `fputc()`：写一个字符

```c
int fputc(int ch, FILE *stream);
```

```c
FILE *fp = fopen("data.txt", "a");
if (fp != NULL) {
    fputc('X', fp);
    fclose(fp);
}
```

如果原文件为 `Hello` 且没有结尾换行，则追加后为 `HelloX`。

`fputc('X', fp)` 只写入字符 `'X'`，**不会自动换行**。

## 4.2 `fputs()`：写字符串

```c
int fputs(const char *str, FILE *stream);
```

```c
fputs(" World", fp);
fputc('!', fp);
```

如果原文件为 `Hello`（没有结尾换行），追加结果为：

```text
Hello World!
```

`fputs()` **不会把 C 字符串结尾的 `\0` 写入文件**，也**不会自动添加 `\n`**。

## 4.3 `fprintf()`：格式化写入

```c
int fprintf(FILE *stream, const char *format, ...);
```

可理解成向指定文件流输出的 `printf()`：

```c
printf("Score: %d\n", 95);       // 输出到 stdout
fprintf(fp, "Score: %d\n", 95); // 输出到 fp
```

### 返回值与 `fscanf()` 不同

- `fscanf()`：**成功赋值的项目数**。
- `fprintf()`：成功时返回**格式化后输出的字符数**，发生输出错误时返回负值。

```c
int n = fprintf(fp, "%d-%d", 123, 45);
// 输出：123-45
// 若成功，n == 6
```

```c
int n = fprintf(fp, "Age: %d\n", 20);
// Age: （5 个字符）+ 20（2 个）+ \n（1 个）= 8
// 若成功，n == 8
```

格式串的 `%d` 自身不按两个字符计算，**以实际输出的数字文本长度为准**。源代码里的 `\n` 表示**一个换行字符**。

> [!tip] 浮点格式
> `fprintf(fp, "%f", 89.99)` 默认输出小数点后 **6 位**，通常得到 `89.990000`；`%.2f` 则显示两位小数：`89.99`。这里的十进制 `89.99` 在常见二进制浮点类型里只是近似存储。

# Part 5｜Lecture 12 课件示例逐行理解

## 5.1 示例一：混合格式读取 `sample.txt`

**课件给出的文件：**

```text
2024 12 16
@ 45%
IP1005
89.99
```

**课件的核心读入顺序：**

```c
int x, y, z;
char a, b, str[1024];

fscanf(file, "%d %d %d", &x, &y, &z);
// x=2024, y=12, z=16；第 1 行末尾 \n 仍未消费

fgetc(file);
// 消费第 1 行末尾 \n

a = fgetc(file);
// a='@'

fscanf(file, "%d", &x);
// 跳过空格；x=45；停在 '%' 前

b = fgetc(file);
// b='%'

fgetc(file);
// 消费第 2 行末尾 \n
fgets(str, 1024, file);
// str="IP1005\n"（假设第 3 行以换行结束）
```

> [!warning] 为什么课件需要那两次单独的 `fgetc(file)`？
> 因为 `fscanf(..., "%d", ...)` 读完整数后，**通常不消费后面的换行符**。如果直接调用 `fgets()`，它可能首先读到的只是 `"\n"`。

**这里的 `89.99`：**课件给出的这段示例并**没有再写一条读取 `89.99` 的语句**。我们在学习讨论中额外练习过：

```c
float value;
fscanf(file, "%f", &value);  // 在流位置到达 89.99 前时，可读得约 89.99
```

此为**学习讨论补充**，不要误当作课件原代码。

> [!note] `fgets` 与额外换行
> 如果 `str` 已含 `"IP1005\n"`，再用 `printf("%s\n", str)` 打印，就会再附加一个换行，因此显示结果中可能出现空行。

## 5.2 示例二：循环读取 `sample_r.txt`

**课件原写法（用于识别陷阱）：**

```c
while (!feof(file)) {
    fscanf(file, "%d %d", &id, &score);
    printf("ID: %d, Score: %d\n", id, score);
}
```

**问题：** `feof()` 不是“下次读取会成功”的预测器。如果文件有 10 条合法记录、最后还有换行符，循环可能第 11 次进入，`fscanf()` 失败，`id`/`score` 却还是上次的值，导致**最后一条被多打印一次**。

**推荐的修正写法（学习讨论）：**

```c
int id, score;

while (fscanf(file, "%d %d", &id, &score) == 2) {
    printf("ID: %d, Score: %d\n", id, score);
}
```

这样保证**两个整数都读取成功才处理一条记录**。

假设文件有：

```text
101 90
102 85
103 hello
104 95
```

只打印前两条。第三次调用的返回值为 `1`：`103` 已赋给 `id`，`hello` 无法赋给 `score`，循环退出；**不会自动恢复并跳到 `104 95`**。

## 5.3 示例三：`"w"` 模式新建并写入

**课件关键代码：**

```c
FILE *file = fopen("sample_w.txt", "w");

fprintf(file, "%d %d %d\n", 2024, 12, 16);
fprintf(file, "@ 45!\n");
fprintf(file, "IP1005\n%f", 89.99);

fclose(file);
```

若打开与写入都成功，格式化输出应为：

```text
2024 12 16
@ 45!
IP1005
89.990000
```

> [!warning] 课件输出展示的小差异
> 合并课件里展示为 `89.9900000`（小数点后 7 位），但代码中的 `%f` 默认精度是**6 位小数**，通常应为 `89.990000`。这里特别保留差异说明，而不悄悄将课件示例改写。

如果改成 `"IP1005\n%.2f"`，最后一行就显示 `89.99`。

## 5.4 示例四：`"a"` 模式追加五条记录

**课件关键代码：**

```c
FILE *file = fopen("sample_r.txt", "a");

fprintf(file, "\n");
for (int i = 1; i <= 5; i++) {
    fprintf(file, "%d %d\n", 202400010 + i, 88);
}

fclose(file);
```

**一次运行新增：**

```text
202400011 88
202400012 88
202400013 88
202400014 88
202400015 88
```

**连续运行两次**：会追加两批相同记录，**一共新增 10 条**。`"a"` 只负责追加，**不会判断 ID 是否重复**。

> [!warning] `fprintf(file, "\n")` 的假设
> 课件在追加前无条件写一个换行，是为了防止原文件最后一行**没有换行符**、新记录黏到原记录后面。
> 但是：**如果原文件已经以 `\n` 结尾，这句又会增加一个空行**。

对下面这种空行，`fscanf(fp, "%d %d", ...)` 的 `%d` 会自动跳过空白，因此仍能读出记录：

```text
101 90

102 85
```

如果换成 `"w"` 并**连续运行两次**，每次打开都会清空旧内容，最终仍然只保留**5 条记录**。

# Part 6｜易错点速查

| 易错想法 | 正确理解 |
|---|---|
| `FILE *fp` 指向磁盘上某个字符 | 它指向 C 标准库管理的文件流对象 |
| `fopen("...", "w")` 要等写入才清空 | **打开成功就清空** |
| `"a"` 会自动加换行 | 不会；是否写 `\n` 要自己决定 |
| 文件读完最后一个字符时 `feof()` 立刻为真 | 通常仍需尝试下一次读取才会设置结束标志 |
| `fgetc()` 可以用 `char` 安全判断 `EOF` | 应用 **`int`** 接收 |
| `fgets()` 遇到 `\n` 会丢弃它 | 会**保留**读取到的 `\n` |
| `fgets()` 会把整个数组剩余位置都清零 | 只确保成功读入的字符串以一个 `\0` 结束 |
| `fscanf("%c",...)` 会跳过换行 | **`%c` 默认不跳过空白**；可写 `" %c"` |
| `fscanf()` 返回成功读取的字符数 | 返回**成功赋值的项目数** |
| `fprintf()` 返回成功赋值的项目数 | 返回**成功输出的字符数** |
| `fscanf()` 失败时所有变量都保持原状 | 可能**部分赋值成功** |
| `fflush()` 成功等于永久写到 SSD | 不一定；可能仍在操作系统缓存中 |
| `while (!feof(fp))` 是安全的读取循环 | 通常应**先读取，检查返回值，再处理** |

## 本讲 I/O 函数总结（与课件对应）

| 函数 | 用途 | 记忆重点 |
|---|---|---|
| `fopen` / `fclose` | 打开 / 关闭文件 | 打开检查 `NULL`；关闭留意失败 |
| `fflush` | 刷新输出流 | 不关闭流；不等于断电安全 |
| `feof` | 检查文件结束标志 | **不是**预测下次是否能读到 |
| `fgetc` / `fputc` | 读 / 写一个字符 | `fgetc` 使用 `int` 接收返回值 |
| `fgets` / `fputs` | 读 / 写字符串 | `fgets` 可能保留 `\n`；`fputs` 不自动换行 |
| `fscanf` / `fprintf` | 格式化读 / 写 | 前者看**赋值数量**；后者看**输出字符数量** |

## 个人学习关联｜Course9Practice

在学生管理系统里写过的安全输入模块已经实践过：

```c
fgets(buffer, sizeof(buffer), stdin);
```

以及检查长度、丢弃残留输入、解析整数等策略。

从终端输入迁移到文件读取时，可以沿用同样的核心思维：

1. **限定缓冲区容量**，避免越界。
2. **先检查返回值**，再使用读到的数据。
3. **识别残留空白/换行/无效字符**。
4. **明确一条记录的边界**，决定出错后是跳过字段、丢弃整行，还是退出。

这部分是我们学习讨论时与个人代码的关联，并非 Lecture 12 原课件的独立章节。
