# 第一节：`scanf()` 的返回值与格式匹配

## 1.1 `scanf()` 的真实工作机制

我们通常写：

```c
int number = 0;
scanf("%d", &number);
```

更精确的理解是：

> `scanf()` 按照格式字符串，从标准输入流 `stdin` 中尝试读取并转换数据。只有转换成功，才会将结果写入对应变量。

`scanf()` 具有返回值，其通常表示**成功赋值的输入项数量**。

对于只有一个 `%d` 的调用：

| 输入情况               | 返回值 | 变量状态       |
| ---------------------- | ------ | -------------- |
| `123`                  | `1`    | 成功赋值为 123 |
| `50`                   | `1`    | 成功赋值为 50  |
| `abc`                  | `0`    | 未获得新值     |
| 输入结束且尚未成功转换 | `EOF`  | 未获得新值     |
| 读取错误且尚未成功转换 | `EOF`  | 未获得新值     |

注意：

```c
int result = scanf("%d", &number);
```

如果用户输入 `123`，则：

```text
number = 123
result = 1
```

`result` 是成功赋值数量，不是输入的整数。

## 1.2 为什么非整数输入会引起死循环？

分析实际练习：

```c
int number = 50;

while (number < 100) {
    scanf("%d", &number);
    printf("%d\n", number);
}
```

输入：

```text
abc
```

执行过程：

1. `number = 50`，循环条件成立。
2. `scanf("%d", &number)` 遇到 `a`，发生匹配失败。
3. `scanf()` 返回 `0`，但程序没有检查。
4. `number` 保持原值 `50`。
5. 字符 `a` 没有被消耗，仍然留在输入流中。
6. 程序输出 `50`，进入下一轮。
7. 下一轮 `scanf()` 再次遇到同一个 `a`，继续失败。

因此产生死循环。

**重要结论：匹配失败并不意味着非法输入会自动被丢弃。**

### 未初始化变量的风险

如果原代码变为：

```c
int number;

while (number < 100) {
    scanf("%d", &number);
}
```

这里还存在另一个问题：`number` 在进入循环条件判断时就已经被读取，而它尚未初始化。

这种行为属于**未定义行为（Undefined Behavior）**。

初始化变量只能避免这一特定问题，并不能自动修复输入匹配失败。

## 1.3 部分匹配成功：`123abc`

考虑：

```c
int number = 50;
int result = scanf("%d", &number);
```

输入：

```text
123abc
```

`%d` 可以成功解析开头的整数 `123`。

结果：

```text
number = 123
result = 1
```

输入流中仍然保留：

```text
abc\n
```

这是因为 `scanf()` 只读取当前转换需要的部分，没有自动要求整行都是合法整数。

因此：

**整数转换成功，不代表整行输入完全合法。**

## 1.4 连续调用 `scanf()` 的后果

```c
int a = 10;
int b = 20;

int r1 = scanf("%d", &a);
int r2 = scanf("%d", &b);

printf("%d %d %d %d\n", a, b, r1, r2);
```

输入：

```text
123abc
```

输出：

```text
123 20 1 0
```

原因：

- 第一次调用成功读取 `123`，返回 `1`。
- 第二次调用遇到残留的 `a`，匹配失败，返回 `0`。
- `b` 没有被修改，仍为 `20`。

### 多个格式说明符

```c
int a = 10, b = 20;
int result = scanf("%d %d", &a, &b);
```

输入：

```text
123 hello
```

得到：

```text
a = 123
b = 20
result = 1
```

虽然格式字符串包含两个 `%d`，但只有第一个整数转换成功。

因此，**`scanf()` 返回值应当与预期成功赋值的输入项数量比较**，不能一律判断是否等于 `1`。

# 第二节：输入流、`getchar()`、字符值与 EOF

## 2.1 标准输入流 `stdin`

`stdin`（Standard Input）是 C 标准库提供的标准输入流。

它可以连接：

- 键盘终端
- 普通文件
- 管道等其他输入来源

输入流可以理解为按顺序提供数据的通道。

例如用户在常见终端环境中输入：

```text
123abc
```

然后按 Enter，程序能够依次读取：

```text
'1' '2' '3' 'a' 'b' 'c' '\n'
```

这里的 `'\n'` 是换行符。

注意：**标准输入流不等于某个固定的键盘缓冲区**。缓冲行为取决于 C 标准库和底层输入环境。

## 2.2 `getchar()` 的作用

```c
int ch = getchar();
```

`getchar()` 从 `stdin` 读取下一个输入字符。

与 `%d` 不同，`getchar()` 不会尝试将连续字符转换成整数，也不会自动跳过空格或换行符。

例如输入：

```text
ABC
```

连续调用 `getchar()`，可以依次获得：

```text
'A'
'B'
'C'
'\n'
```

重要的是：

**`getchar()` 读取字符，但返回类型是 `int`。**

这是为了同时表示正常的字符值以及特殊的 `EOF` 返回值。

## 2.3 ASCII 与字符的整数表示【补充辨析】

计算机中的字符具有对应的整数编码值。

ASCII 是一种经典的字符编码标准。

在 ASCII 兼容系统中：

| 字符   | 十进制编码值 |
| ------ | -----------: |
| `'0'`  |           48 |
| `'1'`  |           49 |
| `'A'`  |           65 |
| `'B'`  |           66 |
| `'a'`  |           97 |
| `' '`  |           32 |
| `'\n'` |           10 |
| `'\0'` |            0 |

例如：

```c
char ch = 'A';

printf("%c\n", ch);
printf("%d\n", ch);
```

在 ASCII 兼容系统上输出：

```text
A
65
```

同一个字符可以按照字符形式或者整数形式显示。

需要注意：C 标准不要求所有实现都采用 ASCII 编码。

### `'0'`、`0` 和 `'\0'` 的区别

| 写法   | 含义       |          数值 |
| ------ | ---------- | ------------: |
| `0`    | 整数零     |             0 |
| `'0'`  | 数字字符 0 | ASCII 下为 48 |
| `'\0'` | NUL 空字符 |             0 |

`'\0'` 是正常存在的零值字符，常用于标记 C 字符串的结束位置。

它不是 `EOF`。

例如：

```c
char text[] = "AB\0CD";
```

数组实际包含：

```text
'A' 'B' '\0' 'C' 'D' '\0'
```

第一个 `'\0'` 来自字符串字面量内部，第二个由字符串字面量自动添加。

因此：

```c
printf("%s\n", text);       // AB
printf("%zu\n", sizeof text); // 6
```

**NUL 是真实的字符值；EOF 不是输入流中的普通字符。**

## 2.4 转义序列【补充辨析】

转义序列（Escape Sequence）是在源代码中表示特殊字符的一种写法。

常见例子：

| 写法 | 含义     |
| ---- | -------- |
| `\n` | 换行     |
| `\t` | 水平制表 |
| `\0` | 零值字符 |
| `\\` | 反斜杠   |
| `\"` | 双引号   |
| `\'` | 单引号   |
| `\r` | 回车     |

例如：

```c
printf("Hello\nWorld");
```

输出：

```text
Hello
World
```

而：

```c
printf("Hello\\nWorld");
```

输出：

```text
Hello\nWorld
```

原因是 `\\` 表示反斜杠本身，后面的 `n` 是普通字符。

注意转义序列在**编译器解释源代码时**发挥作用。

用户直接在终端键入反斜杠和字母 `n`，通常不会被 `getchar()` 自动转换成换行符。

### 关于 `\0` 的补充

`\0` 属于八进制转义序列。

例如，`'\12'` 表示八进制数 `12`，其十进制值为 `10`。在 ASCII 兼容系统中，它通常与 `'\n'` 对应相同的字符值。

当前阶段不需要记忆完整的八进制、十六进制转义规则。

## 2.5 EOF 究竟是什么？

EOF 是 **End Of File** 的缩写。

它是 `<stdio.h>` 中定义的一个宏，用来表示输入函数没有成功读取到所请求的数据，因为：

1. 输入已经到达末尾。
2. 或者发生了读取错误。

`EOF` 是一个负的整数常量表达式，在常见实现中等于 `-1`，但 C 标准没有强制规定必须等于 `-1`。

因此应该写：

```c
if (ch == EOF)
```

而不是：

```c
if (ch == -1)
```

### EOF 不是实际字符

这是学习过程中最重要的一次辨析：

- `'a'`、`'b'`、`'c'`：输入流中的实际数据。
- `EOF`：输入函数报告输入结束或错误的特殊返回值。

因此，不应该说“读取并消耗了 EOF”。

更准确的说法是：

> 尝试读取下一个字符时，发现没有数据可读，于是函数返回 EOF。

## 2.6 为什么 EOF 可以反复返回？

C 标准库的流具有**文件结束指示器（End-of-file Indicator）**。

假设文件内容是 `ABC`，并且没有换行符。

连续读取：

| 读取次数 | 返回结果 |
| -------- | -------- |
| 第一次   | `'A'`    |
| 第二次   | `'B'`    |
| 第三次   | `'C'`    |
| 第四次   | `EOF`    |
| 第五次   | `EOF`    |

第四次读取发现文件结束，设置文件结束指示器。

在没有清除该状态或重新定位文件的情况下，后续读取仍会返回 `EOF`。

**这不是 EOF 残留，而是文件结束状态仍然存在。**

### `feof()` 和 `ferror()`

```c
if (feof(stdin)) {
    puts("End of input.");
}

if (ferror(stdin)) {
    puts("Input error.");
}
```

- `feof(stdin)`：检查文件结束指示器。
- `ferror(stdin)`：检查读取错误指示器。

`feof()` 不能提前预测文件是否即将结束；它检查的是已经发生的读取结果所设置的状态。

## 2.7 `clearerr()` 不会创造输入数据

```c
clearerr(stdin);
```

会清除标准输入流的文件结束和错误指示器。

但它不会自动生成新数据，也不会自动移动文件读取位置。

例如：

```c
clearerr(fp);
int ch = fgetc(fp);
```

如果文件已经读到末尾，没有新增内容，读取位置也没有改变，那么下一次 `fgetc()` 仍可能返回 `EOF`。

与此不同：

```c
rewind(fp);
```

可以在适用的可定位文件流上，将读取位置移回开头，并清除相关状态。

终端和管道通常不能像普通文件那样倒回去。

因此需要区分：

1. **EOF 返回值：** 某次输入操作的结果。
2. **EOF 指示器：** 与流关联的状态。
3. **输入源实际结束：** 已经没有更多可供读取的数据。

清除第二项，不代表第三项自动发生变化。

## 2.8 为什么 `getchar()` 应使用 `int` 接收？

正确写法：

```c
int ch;

while ((ch = getchar()) != EOF) {
    putchar(ch);
}
```

`getchar()` 需要表示所有 `unsigned char` 对应的值，还需要额外表示 `EOF`。

如果使用：

```c
char ch = getchar();
```

在某些平台上可能无法可靠地区分正常输入字节与 `EOF`。

因此，用 `int` 接收 `getchar()` 的返回值是必要的，而不是个人代码风格。

### 为什么不能直接把返回值作为循环条件？

错误示例：

```c
while (ch = getchar()) {
    putchar(ch);
}
```

C 语言中：

- `0` 为假。
- 非 `0` 为真。

所以，正常读取到值为 `0` 的 NUL 字符时，循环会提前结束。

而当 `getchar()` 返回负值 `EOF` 时，条件反而仍然为真，循环可能不断重复。

正确的终止判断应当是：

```c
while ((ch = getchar()) != EOF)
```

# 第三节：`scanf()` 失败后的恢复机制

## 3.1 为什么只检查返回值还不够？

假设：

```c
int result = scanf("%d", &number);

if (result == 0) {
    printf("Invalid input.\n");
}
```

虽然程序识别了格式错误，但输入流中的非法字符仍然存在。

如果立即再次调用 `scanf()`，它很可能再次遇到同一个字符。

因此，正确的恢复过程至少需要：

**检测失败 → 处理残留输入 → 决定重试或退出。**

## 3.2 使用 `getchar()` 丢弃当前行剩余字符

本节最重要的代码：

```c
int ch;

while ((ch = getchar()) != '\n' && ch != EOF) {
}
```

逐步理解：

1. 调用 `getchar()` 获取下一个字符。
2. 把返回值保存到 `ch`。
3. 如果不是换行符，也不是 EOF，继续循环。
4. 如果读取到换行符，结束循环。
5. 如果读取到 EOF，也结束循环。

### 为什么要检测两个条件？

`'\n'` 表示当前输入行结束。

`EOF` 表示输入结束或读取错误。

二者并不等价。

如果只有：

```c
while (getchar() != '\n') {
}
```

当输入源在没有换行符的情况下结束时，循环可能反复得到 `EOF`，无法正常退出。

### 换行符是否会被消耗？

会。

因为表达式：

```c
(ch = getchar()) != '\n'
```

先执行 `getchar()`，再比较。

当读到 `'\n'` 时，换行符已经被取走，之后比较条件才变成假。

### 为什么不说“清空整个输入流”？

这段循环实际上只会**丢弃当前行的剩余字符**。

例如文件包含：

```text
abc
456
789
```

如果处理到第一行的 `abc` 并执行清理循环，循环在第一行换行符处停止。

后面的 `456` 和 `789` 仍然可以继续读取。

因此，准确的表述是：

**Discard the Rest of the Current Line（丢弃当前行剩余内容）。**

## 3.3 `break` 与 `continue` 在输入恢复中的作用

在外层输入循环中：

```c
while (1) {
    // Input logic
}
```

常用两个语句：

| 语句       | 作用                                    |
| ---------- | --------------------------------------- |
| `break`    | 立即退出最近一层包围它的循环或 `switch` |
| `continue` | 跳过当前循环本轮剩余语句，进入下一轮    |

例如：

```c
while (1) {
    if (result == 0) {
        while ((ch = getchar()) != '\n' && ch != EOF) {
        }

        if (ch == EOF) {
            break;
        }

        continue;
    }
}
```

这里：

- 内层的 `while` 负责清理字符。
- 当代码执行到 `if (ch == EOF)` 时，内层循环已经结束。
- 因此该处的 `break` 退出的是外层 `while (1)`。
- 如果未遇到 EOF，则执行 `continue`，开始外层循环的下一轮。

**`break` 不是必然结束程序；它只是退出当前所处的最近一层循环或 `switch`。**

## 3.4 教学示例：三位整数输入

以下是本节讨论过的过渡方案，用于展示返回值检查、字符清理和重试机制的组合。

```c
#include <stdio.h>

int main(void) {
    int number;
    int result;
    int ch;

    while (1) {
        printf("Enter an integer (100-999): ");

        result = scanf("%d", &number);

        if (result == EOF) {
            printf("Input ended or failed.\n");
            break;
        }

        while ((ch = getchar()) != '\n' && ch != EOF) {
        }

        if (result == 0) {
            printf("Invalid integer input.\n");

            if (ch == EOF) {
                break;
            }

            continue;
        }

        if (number < 100 || number > 999) {
            printf("Out of range. Try again.\n");

            if (ch == EOF) {
                break;
            }

            continue;
        }

        printf("Accepted: %d\n", number);
        break;
    }

    return 0;
}
```

这里有四个值得注意的设计点：

**第一，先判断读取结果。**

只有 `scanf()` 成功转换整数之后，才使用 `number` 进行范围验证。

**第二，失败后必须处理残留输入。**

如果遇到 `abc`，清理循环会逐个消耗非法字符，避免下一轮再次遇到同一个 `a`。

**第三，遇到 EOF 时停止无意义的重试。**

输入源结束后，不应该不加判断地执行 `continue`。

**第四，只有格式转换和范围验证通过后，才接受输入。**

本示例要求整数位于 `100–999`。

### 示例行为

| 输入                     | 预期处理                         |
| ------------------------ | -------------------------------- |
| `abc\n`                  | 转换失败，清理本行，重新输入     |
| `50\n`                   | 转换成功但超出范围，重新输入     |
| `456\n`                  | 接受 `456`                       |
| `abc` 后立即 EOF，无换行 | 转换失败，清理至 EOF，结束循环   |
| `456` 后立即 EOF，无换行 | 已成功获取合法整数，可以接受     |
| `123abc\n`               | 会接受 `123`，暴露当前方案的局限 |

## 3.5 重点追踪题：`abc` 后直接 EOF

假设输入源只有：

```text
abc
```

并且末尾没有换行符。

相关逻辑：

```c
result = scanf("%d", &number);

if (result == EOF) {
    break;
}

while ((ch = getchar()) != '\n' && ch != EOF) {
}

if (result == 0) {
    if (ch == EOF) {
        break;
    }

    continue;
}
```

实际执行过程：

1. `scanf()` 首先遇到 `a`，无法转换成整数。
2. 此时返回 `0`，而不是 `EOF`。
3. 第一个 `if (result == EOF)` 不成立。
4. `getchar()` 依次消耗 `a`、`b`、`c`。
5. 再次读取发现输入结束，返回 `EOF`。
6. 清理循环结束，此时 `ch == EOF`。
7. `result == 0` 成立，进入对应分支。
8. `ch == EOF` 成立，执行第二个 `break`。
9. 外层输入循环结束。

学习者已独立完成该题，并准确解释了两个 `break` 的执行条件。

**本题核心：`scanf()` 的匹配失败与后续 `getchar()` 检测到 EOF，可以先后发生。**

# 四、目前方案的限制【重要】

虽然 `scanf()` + `getchar()` 已经能够解决不少输入恢复问题，但它还不是严格的最终方案。

## 4.1 `123abc` 仍然可能被接受

```c
scanf("%d", &number);
```

会成功读取开头的 `123`，返回 `1`。

后面用 `getchar()` 丢弃 `abc`，并不能证明用户输入的整行都是合法整数。

**清理残留字符与验证残留字符是否合法，是两件不同的事。**

## 4.2 超出 `int` 范围的输入

当用户输入超出 `int` 可表示范围的数字时，`scanf("%d", ...)` 的转换可能产生未定义行为。

因此，仅仅检查返回值，不能保证能够安全处理任意长度的数字。

这也是后续需要学习 `strtol()` 等转换方式的原因之一。

## 4.3 不能无条件清理整行

如果程序原本允许一行输入多个整数，例如：

```text
10 20 30
```

在读取第一个整数后立即丢弃整行，就会丢失后面的 `20` 和 `30`。

因此，是否按行清理输入，必须由程序的输入格式要求决定。

## 4.4 不建议使用 `fflush(stdin)`

`fflush()` 的标准用途主要是处理输出流。

在 ISO C 中，对普通输入流调用：

```c
fflush(stdin);
```

不能作为通用、可移植的清空输入方案。

某些编译环境可能提供额外支持，但不应该将它视为标准 C 的输入健壮性处理方法。

# 五、易错点速查

| 易错理解                            | 正确理解                             |
| ----------------------------------- | ------------------------------------ |
| `scanf()` 返回用户输入的整数        | 返回成功赋值的输入项数量             |
| 输入 `abc` 后，`scanf()` 自动丢弃它 | 匹配失败时，非法字符可能仍留在输入流 |
| `123abc` 一定使 `%d` 返回 0         | `%d` 可以成功读取 123，返回 1        |
| `scanf("%d %d")` 成功时返回 1       | 两项都成功赋值时返回 2               |
| `scanf()` 失败会自动把变量清零      | 未成功赋值的变量保持原有状态         |
| `getchar()` 返回类型是 `char`       | 返回类型是 `int`                     |
| `'0'` 与 `'\0'` 相同                | ASCII 下分别是 48 和 0               |
| EOF 是留在输入流中的特殊字符        | EOF 是输入函数的特殊返回值           |
| 读完最后一个字符就已经返回 EOF      | 通常需要下一次读取尝试才检测到 EOF   |
| `clearerr()` 会产生新输入           | 只清除流状态，不会创造数据           |
| `while (ch = getchar())` 能检测 EOF | EOF 是非零负值，不能这样判断         |
| `break` 必然结束程序                | 退出最近一层循环或 `switch`          |
| 清理循环会清空全部 stdin            | 通常只丢弃当前行的剩余字符           |
| 清理掉 `abc` 就证明输入合法         | 清理不是验证                         |
| `scanf` 返回 1 就能安全处理任何整数 | 超范围转换仍可能产生未定义行为       |
