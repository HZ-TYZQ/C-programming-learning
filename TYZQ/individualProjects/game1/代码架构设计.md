# 《下一站，生日》代码架构设计决策

对应策划：[游戏策划.md](./游戏策划.md)  
对应 UI 决策：[UI设计.md](./UI设计.md)

## 1. 工程结构与构建约定

沿用 C11 多文件工程习惯，源码与编译产物分离，主程序与单元测试独立构建：

```text
game1/
├── Makefile
├── 游戏策划.md
├── UI设计.md
├── 代码架构设计.md
├── docs/                 # 16 份剧情定稿文案（参考源稿）
├── builds/               # .o 与可执行文件（主程序 builds/game，测试 builds/test_game）
├── save.txt              # 运行时在 game1/ 根目录生成的自动存档文件
└── src/
    ├── game.h / game.c   # 核心数据模型、世界静态表、经济与事件纯规则、状态校验（零 I/O）
    ├── save.h / save.c   # 文件 I/O：自动存档、读档、存档摘要（严格逐行解析 + 原子写入）
    ├── input.h / input.c # 安全输入：区间整数、默认最大值数量、剧情步进、二次确认（区分 EOF）
    ├── ui.h / ui.c       # 清屏、ANSI 配色、sleepMs、UTF-8 流式打字机、各类面板绘制
    ├── story.h / story.c # 16 份剧情只读数组 + 开场/日常/温泉/结局/事件剧本段
    ├── event.h / event.c # 5 颗星抵达事件演出与交互调度（状态变更调用 game.c）
    ├── main.c            # 主菜单、选起点、Day 1~5 主循环、自动存档、生日结局流程
    └── test.c            # 独立单元测试（覆盖 game 与 save，无需人工交互）
```

- **编译选项**：`gcc -std=c11 -Wall -Wextra -Wpedantic -g`
- **构建与运行约定**：
  - `Makefile` 显式声明头文件依赖（如 `game.h`、`ui.h`、`input.h`、`save.h`），保证修改头文件后自动重编相关 `.o`；
  - 支持增量验证：`make test`（Step 1 起可用）、`make run`（固定在 `game1/` 根目录运行 `./builds/game`，避免在 `builds/` 下产生 `save.txt` 后被 `make clean` 误删）；
  - 根目录遗留的 UI 原型（`ui_demo*`）待 Step 3 拆分完 `input.c` / `ui.c` 后清理。
- **代码风格**：Allman 花括号风格、显式写 `struct Name` / `enum Name`、头文件加 include guard、模块内部辅助函数加 `static`、只读指针参数加 `const`。
- **剧情文本决策**：16 份剧情统一以只读 `const struct StoryLine[]` 数组编译进 `story.c`，避免相对路径问题，单可执行文件随处可跑；文件 I/O 聚焦于存档/读档的健壮性实践。

## 2. 模块职责与单向依赖

各模块保持严格单向依赖（有向无环图，无循环 `#include`）：

```text
main.c ──▶ event.c ──▶ story.c ──▶ ui.c ──▶ input.c
  │           │           │         │
  │           ├───────────┴─────────┤
  ├──▶ save.c ┴─────────────────────┼──▶ game.c
  └─────────────────────────────────┘
```

> 说明：`struct StoryLine`、`enum LineType`、`struct StoryContext` 与 `enum NoticeKind` 均定义在 `ui.h` 中，由 `story.h` 与 `event.c` 引用，彻底避免 `story.h <-> ui.h` 循环依赖。

| 模块 | 职责定位 | 典型对外接口 |
| --- | --- | --- |
| `game.h/.c` | 纯数据、规则与校验层（禁止 `printf`/输入/文件） | `initGame()`、`getBuyPrice()`、`getSellPrice()`、`canTravel()`、`getNeighbors()`、`getSellGoodAt()`、`getBuyGoodsAt()`、`getCargoUsed()`、`buyGood()`、`sellGood()`、`travelToPlanet()`、`finishDay()`、`settleBirthdayGift()`、`validateGameState()` 及 5 个事件的纯状态结算函数（`canTriggerArrivalEvent()`、`applyBookEvent()`、`applyFlowerEvent()`、`applyClockEvent()`、`applyMirrorEvent()`、`applyLuckEvent()`） |
| `save.h/.c` | Course 12 文件 I/O 持久化层（统一接收 `path`） | `DEFAULT_SAVE_PATH`、`saveGame(path, state)`、`loadGame(path, outState)`、`peekSaveSummary(path, outSummary)`、`hasValidSave(path)` |
| `input.h/.c` | 终端安全输入层（严格区分 EOF） | `enum StoryStep`、`readIntInRange()`、`readQuantityDefaultMax()`、`waitStoryStep()`、`waitEnter()`、`confirmAction()` |
| `ui.h/.c` | 终端渲染与流式打字机层 | `clearScreen()`、`sleepMs()`、`getSpeedMode()`、`cycleSpeedMode()`、`typePrint()`、`storyBegin()`、`storyPlayChunk()`、`storyWaitEnd()`、`drawStatusHeader()`、`drawStartPlanetScreen()`、`drawTravelScreen()`、`drawStarMap()`、`drawMarketScreen()`、`drawBirthdayScreen()`、`drawEndingSummary()` |
| `story.h/.c` | 16 份只读剧本与情景播放（返回 `1` 正常 / `0` EOF） | `playBeginning()`、`playDayNight(int day)`、`playHotSpring(const struct GameState *)`、`playEnding(int choice, int moneyBeforeGift, int moneyAfterGift, unsigned int flags)` 及 5 个事件的剧本段播放 |
| `event.h/.c` | 5 颗星抵达事件演出与交互调度 | `runArrivalEvent(struct GameState *state)`（播剧情、显资源、验选项，调用 `game.c` 结算） |
| `main.c` | 游戏顶层流程控制 | `srand((unsigned int)time(NULL))`、主菜单 → 新游戏/继续 → 选起点 → Day 1~5 循环 → 自动存档 → 生日购礼与结局结算 |
| `test.c` | 自动化单元测试 | 仅依赖 `game.h` 与 `save.h`，覆盖经济、航线、5 个事件纯规则、`validateGameState()` 不变量、正常存档读写与各类坏档拦截（使用 `"builds/test_save.txt"` 并在结束后 `remove()`，绝不碰正式 `save.txt`） |

## 3. 核心数据结构（`game.h`）

```c
#define PLANET_COUNT   5
#define GOOD_COUNT     5
#define MAX_DAYS       5
#define TRIPS_PER_DAY  2
#define START_MONEY    80
#define TARGET_MONEY   720
#define PAPER_PRICE    150
#define BASE_CARGO     5
#define EXPANDED_CARGO 7

enum PlanetId
{
  PLANET_BOOK = 0,    /* 书之星 */
  PLANET_FLOWER = 1,  /* 花之星 */
  PLANET_CLOCK = 2,   /* 钟之星 */
  PLANET_MIRROR = 3,  /* 镜之星 */
  PLANET_LUCK = 4     /* 运之星 */
};

enum GoodId
{
  GOOD_FILM = 0,      /* 微缩胶卷 */
  GOOD_TEA = 1,       /* 安神花茶 */
  GOOD_GEAR = 2,      /* 精密齿轮 */
  GOOD_INK = 3,       /* 星光墨水 */
  GOOD_BADGE = 4      /* 幸运徽章 */
};

enum GamePhase
{
  PHASE_TRAVEL = 0,   /* 每日选星与跑商阶段 */
  PHASE_BIRTHDAY = 1  /* 第五天温泉后，待选生日礼物阶段 */
};

enum GiftChoice
{
  GIFT_CHOCOLATE = 1, /* 甜之星巧克力 720 G */
  GIFT_PAPER = 2      /* 纸之星手作纸 150 G */
};

/* 10 个状态位统一使用位掩码管理 */
#define FLAG_ITEM_BOOKMARK      (1u << 0)  /* 持有干花书签 */
#define FLAG_ITEM_KEY           (1u << 1)  /* 持有黄铜钥匙 */
#define FLAG_EV_BOOK_DONE       (1u << 2)  /* 0 书之星事件已完成 */
#define FLAG_EV_FLOWER_DONE     (1u << 3)  /* 1 花之星事件已完成 */
#define FLAG_EV_CLOCK_DONE      (1u << 4)  /* 2 钟之星事件已完成 */
#define FLAG_EV_MIRROR_DONE     (1u << 5)  /* 3 镜之星事件已完成（暂缓离开不置位） */
#define FLAG_EV_LUCK_DONE       (1u << 6)  /* 4 运之星事件已完成（50%未触发不置位） */
#define FLAG_TOPIC_BOOKMARK     (1u << 7)  /* 解锁温泉话题：书签背面的花名 */
#define FLAG_TOPIC_STARMAP      (1u << 8)  /* 解锁温泉话题：生日那天的星空 */
#define FLAG_EV_MIRROR_DEFERRED (1u << 9)  /* 3 镜之星曾暂缓离开，重返改播短开场（完成后清除） */
#define FLAG_ALL_VALID          ((1u << 10) - 1u)

struct GameState
{
  int day;                /* 当前天数 1 ~ 5 */
  int phase;              /* PHASE_TRAVEL 或 PHASE_BIRTHDAY */
  int planet;             /* 当前星球 0 ~ 4 */
  int tripsLeft;          /* 今日剩余航程 0 ~ 2 */
  int money;              /* 当前资金（>= 0） */
  int cargoCap;           /* 货舱上限（5 或 7） */
  int cargo[GOOD_COUNT];  /* 5 种普通商品持有数量 */
  unsigned int flags;     /* 信物 / 事件 / 温泉话题位掩码 */
};
```

### 世界静态数据表（`game.c` 内部只读数组）
- `BUY_PRICE[5][5]`：玩家向当地商店购入单价（`0` 表示不出售）。
- `SELL_PRICE[5][5]`：玩家向当地商店卖出单价（`0` 表示不收购）。
- `ADJACENCY[5][5]`：对称无向邻接矩阵（`1` 可直达，`0` 不可直达），精确表达 6 条航线。
- `PLANET_NAMES[5]`、`PLANET_INTROS[5]`、`GOOD_NAMES[5]`：名称与简介文本。

### 关键规则落地细节
- **起点不触发事件**：开局选完起点后直接进入当地市场，**不调用** `runArrivalEvent()`；仅在执行 `travelToPlanet()` 飞抵目标星后调用，自然满足“起点首次不触发，日后飞回正常触发”。
- **镜之星「暂缓离开」**：仅在 `cargo[GOOD_FILM] == 0` 时可选；暂缓时置位 `FLAG_EV_MIRROR_DEFERRED` 且不置位 `FLAG_EV_MIRROR_DONE`；完成镜之星事件（选项 1 或 2）时，清除 `FLAG_ITEM_KEY` 与 `FLAG_EV_MIRROR_DEFERRED` 并置位 `FLAG_EV_MIRROR_DONE`。
- **生日购礼结算**：`settleBirthdayGift(struct GameState *state, int choice, int *outMoneyBefore)` 在扣款前记录并返回 `moneyBefore`（选 `GIFT_CHOCOLATE` 必须满足 `money >= TARGET_MONEY`），随后 `main.c` 将 `moneyBefore` 与 `state.money`（扣后余额）一并传给 `playEnding()`，避免扣款顺序导致的分支误判。

## 4. 存档文件 I/O 规范（`save.h / save.c`）

### 4.1 存档格式（纯文本键值对，`save.txt`，固定精确 9 行）

```text
NEXT_STOP_BIRTHDAY_V1
day 3
phase 0
planet 2
trips_left 2
money 340
cargo_cap 5
cargo 2 0 1 0 0
flags 5
```

### 4.2 自动存档时机、恢复点与终局保留策略
- **Day 1～4 晚间日常结束后**：推进状态为 `day = day + 1, phase = PHASE_TRAVEL, tripsLeft = 2`，立即写入 `save.txt`。读档后直接从次日选星界面恢复。
- **Day 5 温泉日常结束后**：推进状态为 `day = 5, phase = PHASE_BIRTHDAY, tripsLeft = 0`，立即写入 `save.txt`。读档后直接进入生日礼物选择界面。
- **生日结局结束后**：**不覆写也不删除 `save.txt`**（保留 Day 5 温泉后的 `PHASE_BIRTHDAY` 存档），方便玩家回到主菜单后点「继续旅程」体验另一个礼物结局。

### 4.3 读写健壮性规则（Course 12 重点）
- **路径解耦与原子写入**：
  - `saveGame` / `loadGame` / `peekSaveSummary` / `hasValidSave` 全部接收 `const char *path`（`save.h` 提供 `#define DEFAULT_SAVE_PATH "save.txt"`）；
  - 临时文件路径由 `path` 动态拼接为 `"%s.tmp"`，写入全部 9 行并检查每次 `fprintf` 与 `fclose() != EOF` 后，再调用 `<stdio.h>` 的 `rename(tmpPath, path)` 覆盖目标文件；**任意一步失败均调用 `remove(tmpPath)` 清理残留临时文件**。
- **严格逐行解析（禁止用 `fscanf` 解析数值）**：
  - 检查 `fopen()` 非 `NULL`，严格使用 `fgets` 精确读取 9 行（检查每行完整无超长截断、去掉末尾 `\r\n`）；
  - 校验第 1 行为精确版本号 `NEXT_STOP_BIRTHDAY_V1`，其余 8 行精确匹配键名前缀后，使用 `strtol` / `strtoul` 解析数值并检查 `errno != ERANGE` 与行尾无多余垃圾字符；无符号字段 `flags` **显式拒绝负号 `'-'`**；
  - 确认第 10 次 `fgets` 返回 `NULL`（拒绝文件末尾多余行）。
- **存档摘要复用**：`peekSaveSummary(path, outSummary)` 直接复用 `loadGame()` 读出合法状态后提取 `day`、`phase`、`planet`、`money`，保证摘要展示与读档校验 100% 一致。
- **完整语义合法性校验（`validateGameState`，位于 `game.c` 供 `save.c` 与 `test.c` 共用）**：
  1. **阶段与日程组合**：
     - `phase == PHASE_TRAVEL`：`1 <= day <= MAX_DAYS` 且 `1 <= tripsLeft <= TRIPS_PER_DAY`（禁止 `tripsLeft == 0`）；
     - `phase == PHASE_BIRTHDAY`：必须 `day == MAX_DAYS && tripsLeft == 0`；
     - `0 <= planet < PLANET_COUNT`，`money >= 0`，`cargoCap == BASE_CARGO || cargoCap == EXPANDED_CARGO`，`(flags & ~FLAG_ALL_VALID) == 0`。
  2. **货舱防有符号整型溢出求和**：逐项校验 `0 <= cargo[i] && cargo[i] <= cargoCap` 且 `cargo[i] <= cargoCap - used`，再执行 `used += cargo[i]`。
  3. **书签支线不变量**：
     - `!(flags & FLAG_EV_BOOK_DONE)`：无 `FLAG_ITEM_BOOKMARK`、无 `FLAG_EV_FLOWER_DONE`、无 `FLAG_TOPIC_BOOKMARK`，且 `cargoCap == BASE_CARGO`；
     - `(flags & FLAG_EV_BOOK_DONE) && !(flags & FLAG_EV_FLOWER_DONE)`：必有 `FLAG_ITEM_BOOKMARK`、无 `FLAG_TOPIC_BOOKMARK`，且 `cargoCap == BASE_CARGO`；
     - `(flags & FLAG_EV_FLOWER_DONE)`：以下二选一必恰好成立其一：
       - 赠出扩仓分支：`cargoCap == EXPANDED_CARGO && !(flags & FLAG_ITEM_BOOKMARK) && !(flags & FLAG_TOPIC_BOOKMARK)`
       - 保留话题分支：`cargoCap == BASE_CARGO && (flags & FLAG_ITEM_BOOKMARK) && (flags & FLAG_TOPIC_BOOKMARK)`
  4. **钥匙支线不变量**：
     - `!(flags & FLAG_EV_CLOCK_DONE)`：无 `FLAG_ITEM_KEY`、无 `FLAG_EV_MIRROR_DONE`、无 `FLAG_EV_MIRROR_DEFERRED`、无 `FLAG_TOPIC_STARMAP`；
     - `(flags & FLAG_EV_CLOCK_DONE) && !(flags & FLAG_EV_MIRROR_DONE)`：必有 `FLAG_ITEM_KEY`、无 `FLAG_TOPIC_STARMAP`（`FLAG_EV_MIRROR_DEFERRED` 可 0 可 1）；
     - `(flags & FLAG_EV_MIRROR_DONE)`：无 `FLAG_ITEM_KEY`、无 `FLAG_EV_MIRROR_DEFERRED`（`FLAG_TOPIC_STARMAP` 可 0 可 1）。
  - 任意校验不通过即返回失败，且不污染调用者传入的 `struct GameState`。

## 5. 五步分阶段开发计划

1. **Step 1 · 核心规则与测试骨架**：编写 `Makefile`（含头文件依赖与 `test` / `run` 目标）、`game.h/.c`、`test.c`，完成世界静态表、买卖计算、航线查询、货舱与位掩码、5 个事件纯结算函数及完整 `validateGameState()`，并通过 `make test` 零警告。
2. **Step 2 · 存档文件 I/O**：编写 `save.h/.c`（路径参数 + 严格 9 行 `fgets`/`strtol`/`strtoul` 解析 + `"%s.tmp"` 原子写入）；在 `test.c` 中用 `"builds/test_save.txt"` 覆盖正常读写、摘要读取及缺行/多行/负 flags/超限溢出/flag 矛盾组合坏档拦截，测试完 `remove()` 清理。
3. **Step 3 · 输入与 UI 渲染层**：基于 [ui_demo_simple.c](./ui_demo_simple.c) 拆分出 `input.h/.c`（严格区分 EOF）与 `ui.h/.c`（`_POSIX_C_SOURCE` 置首行、流式 `StoryContext`、物理行折行翻页、`notice[256]`+`NoticeKind`、各类面板与结算卡）；验证编译通过后清理根目录旧 Demo 产物。
4. **Step 4 · 主循环闭环**：编写 `main.c`（启动 `srand(time(NULL))`、主菜单存档覆盖确认、选起点、Day 1~5 循环、第 5 天选星 `[0]` 与终站未清仓强警告、自动存档提示、保留 Day 5 存档与终章结算卡），先用占位提示打通完整可玩骨架。
5. **Step 5 · 剧本与事件接入及验收**：编写 `story.h/.c`（录入 16 份定稿文案，统一 5 位 NPC 署名与格式细节）与 `event.h/.c`（接入 5 个抵达事件与 50% 运之星概率）。重点回归验收：起点首日不触发但重访触发、镜之星暂缓离开后重返短开场、运之星 50% 未触发不置位与满仓折现 25 G、温泉 4 种话题组合、纸之星 `< 150 G` / `>= 150 G` / `>= 720 G` 分支、`PHASE_BIRTHDAY` 读档直达购礼界面，以及 `Ctrl+D` EOF 安全退出。
