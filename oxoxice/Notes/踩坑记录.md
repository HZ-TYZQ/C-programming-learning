# 踩坑记录

这份文件只写**我本人真的写错过的**东西，不是知识点摘抄。

每一条都附三样：当时写错的样子、编译器报了什么、正确写法。错的过程比正确的答案值钱——因为下次很可能还是在同一个地方翻车。

内容覆盖 C++ 第 1~4 章，以及实验 1、2、3 和第一次作业。

> 阅读顺序：**先看每条的「现象」，猜一下哪里错了，再看答案。** 直接看正确代码记不住。

## 一、输入 `cin`

### 1. `cin` 中间写了逗号

```cpp
cin >> a, b, c;            // 错
```

```cpp
cin >> a >> b >> c;        // 对
```

**现象**：实验 3 第 2 题，输入 `3 3 3` 却输出「不能构成三角形」；输入什么都一样，永远走 `else` 那一支。

**原因**：`,` 是**逗号运算符**，`(cin >> a), b, c` 的意思只是「读入 a，然后取 b 的值，再取 c 的值」。`b`、`c` 从头到尾没有被赋值，是栈上的垃圾数据。用探针打印出来是：

```
a = 3
b = 6.95146e-310
c = 6.95146e-310
```

三个 `if` 全拿垃圾值去比，必然全假，最后只能落到 `else`。

**编译器**：`warning C4700: 使用了未初始化的局部变量"b"`

### 2. `cin` 结尾写成冒号

```cpp
cin >> a:                  // 错
cin >> a;                  // 对
```

**现象**：实验 3 第 4 题，程序怎么都编译不过。

**编译器**：`error C2143: 语法错误: 缺少";"`

`cin >> a;` 后面接 `switch` 的时候眼花很容易打成冒号，因为 `switch` 和 `case` 满屏都是冒号。

### 3. `cin` 一旦失败就锁死

```cpp
int a, b;
cin >> a >> b;
int c;
cin >> c;                  // 前面失败过，这一行什么都读不进来
```

**现象**：输入 `1 abc`，结果是 `a = 1, b = 0`，而 `c` 保持原值不变。

**原因**：`cin` 遇到类型不匹配会进入 fail 状态，**之后所有 `cin` 都直接返回、不再读键盘**。要恢复得先 `cin.clear()` 清状态，再清掉缓冲区里的残留。

现在先记住：**调试时看到「第二次输入被跳过」，先怀疑第一次输入格式错了。**

## 二、分号、冒号、全角字符

### 4. 少一个分号，报错报在下一行

```cpp
int fact, sum;
fact = 1                   // ← 少了分号
sum = 0
```

**现象**：作业第 3 题（阶乘之和）编译报错，报的位置却在 `sum` 那一行。

**编译器**：`error C2146: 语法错误: 缺少";"(在标识符"sum"的前面)`

**要看懂这条**：编译器是读到 `sum` 才发现「上一句没结束」。**报错的行号往往不是真正出错的行**，往前找一行。

### 5. `do-while` 后面也要分号

```cpp
do {
    cout << i;
    i++;
} while (i < 3)            // ← 少了分号
```

**编译器**：`error C2143: 语法错误: 缺少";"(在"return"的前面)`

`while` 语句不加分号，但 `do...while(...)` **必须**加分号。这是唯一一个括号后面还要分号的循环。

### 6. 全角符号

```cpp
if (ch >= 'A' ｜ ch <= 'Z')        // 错：这是全角竖线 ｜
if (ch >= 'A' || ch <= 'Z')        // 对：两个半角竖线 ||
```

```cpp
cout << “占一天比的” << zhanbi;     // 错：全角引号 “ ”
cout << "占一天比的" << zhanbi;      // 对
```

**编译器**：`error C2146: 语法错误: 缺少")"(在标识符"｜"的前面)`

全角括号 `（）`、全角分号 `；`、全角冒号 `：`、全角逗号 `，` 一样会报错。

**唯一例外**：字符串**里面**的中文标点是内容，随便写——`cout << "请输入："` 里的全角冒号是对的。**只有代码部分（括号、引号、分号、运算符）必须是半角。**

## 三、`=` 和 `==`

### 7. 把比较写成了赋值

```cpp
if (n % i = 0)             // 错
if (n % i == 0)            // 对
```

**编译器**：`error C2106: '=': 左操作数必须为左值`

**这是最幸运的一种错**——`n % i` 是临时值，不能赋值，编译器直接拦住。

**不幸的是另一种**：

```cpp
int count = 0;
if (count = 0)             // 能编译！但恒假
```

`count = 0` 的**表达式的值**就是 0，当条件用就是「假」。程序逻辑全错，编译一点警告都没有，跑起来才发现「怎么永远不进这个分支」。

**习惯**：比较常量时把常量写左边，`if (0 == count)`，写错成 `if (0 = count)` 立刻报错。

### 8. 该用 `==` 的地方用了 `<=`

```cpp
if (m == 0)                // BMI 题：只有身高恰好等于 0 才报错
if (m <= 0)                // 正确：身高 <= 0 都该报错
```

**现象**：输入负的身高，`m == 0` 判不出来，程序继续往下跑，算出负的 BMI。

**原因**：`==` 是「恰好等于」，`<=` 是「小于或等于」。**要挡异常输入，用 `<=`；要判等值，才用 `==`。**

### 9. `=` 混进 `cout` 的链式输出

```cpp
cout << "运费" << 30 = (w - 5) * 3 << "元";     // 错
cout << "运费" << 30 + (w - 5) * 3 << "元";     // 对
```

**编译器**：`error C2296: '<<': 无效，因为左操作数的类型为 'double'`

## 四、区间和边界

### 10. `0 < w <= 1` 在 C++ 里不是区间

```cpp
else if (0 < w <= 1)       // 错，恒真
else if (w <= 1)           // 对，上界已经由前面的分支保证了
```

**原因**：C++ 里 `0 < w <= 1` 等价于 `(0 < w) <= 1`。

- `w > 0` 时 `(0 < w)` 得 `1`，再算 `1 <= 1`，**永远成立**
- `w <= 0` 时 `(0 < w)` 得 `0`，再算 `0 <= 1`，**也成立**

所以这个条件**永远为真**，后面所有分支都成了摆设。数学里的「区间连写」在 C++ 里必须拆成 `w > 0 && w <= 1`。

**但更好的写法是只用上界**：如果分支已经按从小到大排好，前面已经挡掉了小的情况，每个 `else if` 只需要写 `w <= 1`、`w <= 5`。

### 11. 阶梯判断要「从大到小，只写下限」

实验 3 第 1 题（显存判断）的正确套路：

```cpp
if (vram >= 24)          ...
else if (vram >= 10)     ...     // 能到这里，说明 vram < 24
else if (vram >= 4)      ...     // 能到这里，说明 vram < 10
else                     ...     // vram < 4
```

**顺序反了会全错**。把 `vram >= 4` 放最前面，24 和 16 都会被它抢先命中，全部判成「仅支持模型推理」。

**边界归属**：题目写「≥」就包含边界。`10` 属于微调档，`9.99` 掉到推理档；判断条件里的 `>=` 写成 `>`，边界值就全错。

## 五、`switch`

### 12. `case` 后面不能写条件

```cpp
switch (s) {
    case s >= 90: ...      // 错
    case 90:      ...      // 对
}
```

**编译器**：`error C2051: case 表达式不是常量`

`case` 后面只能是**常量**，不能写变量、不能写比较、不能写范围。**范围判断只能用 `if-else`。**

### 13. `switch` 的表达式不能是小数

```cpp
double x = 1.5;
switch (x) { ... }         // 错
```

**编译器**：`error C2450: 类型为"double"的 switch 表达式无效`

`switch` 只接受整型（`int`、`char`）。

### 14. 漏写 `break` 会一路往下穿

```cpp
case 3: cout << "春";      // 漏了 break
case 4: cout << "夏";      // 会继续执行
```

**现象**：输入 3，输出「春夏秋冬」。

**这是特性不是 bug**——实验 3 第 4 题正是用它来减少分句：几个 `case` 摞在一起，中间不写语句也不写 `break`，最后共用一个 `break`。

**区别就一句话：想「共用同一段代码」就故意不写 `break`；想「各自独立」就必须写 `break`。**

### 15. `default` 的位置

`default` 可以放在 `switch` 里任何位置（放最后只是习惯），它接住所有没被 `case` 命中的值。

实验 3 第 4 题冬季是 12、1、2，在数轴上**不连续**，所以要么显式写 `case 12: case 1: case 2:`，要么用 `default` 兜住。

**注意**：如果不先判合法性就把 `-2` 塞进 `switch`，它会被 `default` 接住，输出「-2月处于冬季」。

## 六、变量

### 16. 变量没初始化——编译器只警告，不报错

```cpp
int total;
cout << total;             // 能编译！但值是垃圾
```

**编译器**：`warning C4700: 使用了未初始化的局部变量"total"`（**警告，不是错误**）

**这就是最危险的一类**：能编译、能运行，结果看运气。

三个真实案例：

| 场景 | 表现 |
|---|---|
| 作业第 3 题 `int fact, sum;` 直接进循环 | 结果是垃圾数 |
| 实验 3 第 2 题的 `b`、`c`（逗号运算符那个坑） | 所有判断失败 |
| 变量名改了但赋值没跟上 | `v` 未声明 / `cost` 未声明 |

**习惯**：声明时就给初值。`int fact = 1, sum = 0;`

### 17. 声明的名字和用的名字不一致

```cpp
double a, b;               // 声明的是 a、b
...
cost = v * 2.02;           // 用的是 v、cost
```

**编译器**：`error C2065: "v": 未声明的标识符`

改动代码时变量名只改了一半，是最常见的低级错误。**看到 C2065，先检查是不是名字写岔了，而不是「变量没定义」。**

### 18. 标识符不能以数字开头

```cpp
int 2score = 90;           // 错
int score2 = 90;           // 对
```

**编译器**：`error C2059: 语法错误:"user-defined literal"`

### 19. `const` 定义的东西不能再赋值

```cpp
const double PI = 3.14;
PI = 3.14159;              // 错
```

**编译器**：`error C3892: "PI": 赋值给类型为 'const double' 的常量限定变量`

### 20. `char` 用单引号，字符串用双引号

```cpp
char ch = "A";             // 错：这是字符串
char ch = 'A';             // 对：这是单个字符
```

**编译器**：`error C2440: "初始化": 无法从"const char [2]"转换为"char"`

**记法**：`'A'` 是一个字符（1 字节），`"A"` 是一个字符加一个结束符 `\0`（2 字节）。`[2]` 就是在告诉你这一点。

### 21. 数字前导 0 表示八进制

```cpp
int x = 08;                // 错：八进制里没有 8
int x = 8;                 // 对
```

**编译器**：`error C2041: 非法的数字"8"(用于基"8")`

写 `010` 不是十，是八。**补零只在输出格式里用（`setw(2) << setfill('0')`），绝不要在数字字面量前面随手补零。**

## 七、分支的顺序

### 22. 等边必须排在等腰前面，而且要用 `else if`

```cpp
if (a == b && b == c)      cout << "等边";
if (a == b || b == c || a == c)  cout << "等腰";    // 错：两个并列的 if
```

**现象**：输入 `4 4 4`，输出**两行**——「可以构成等边三角形」和「可以构成等腰三角形」。

**原因**：等边三角形**一定也是等腰三角形**，第二个条件必然跟着成立。

```cpp
if (a == b && b == c)            cout << "等边";
else if (a == b || b == c || a == c)  cout << "等腰";   // 对
else                              cout << "一般";
```

**两条规律**：越特殊的条件越放前面；同一个问题的几种情况之间必须用 `else if`，不能用并列的 `if`。

### 23. 先判「能不能构成」，再判「是哪一种」

```cpp
// 错：先判类型
if (a == b || b == c || a == c)  cout << "等腰";
else if (a + b > c && ...)       cout << "一般";
```

输入 `1 1 2`：`a == b` 成立，直接输出「等腰三角形」。**1、1、2 根本围不成三角形。**

正确结构是两层嵌套：

```
if (能构成三角形)
{
    if (等边)      ...
    else if (等腰) ...
    else          一般
}
else    不能构成
```

**「能不能构成」是唯一的门，先过门，再分房间。**

### 24. 发现输入非法要 `return`，不能只是打印一句

```cpp
if (n <= 0)
{
    cout << "请输入正确的n" << endl;
}
// 少了 return，程序继续往下算
```

**现象**：输入 0 或负数，程序打印完错误提示后**继续算阶乘**，输出一个垃圾结果。

两种修法：

```cpp
// 修法 A：立刻结束
if (n <= 0) { cout << "请输入正确的n" << endl; return 1; }
```

```cpp
// 修法 B：用 else 把正常流程包起来
if (n <= 0) { cout << "请输入正确的n" << endl; }
else        { /* 正常的计算 */ }
```

实验 3 第 3 题（阶梯气费）就是这个坑：输入 `-100`，打印「数据输入错误！」之后，程序**继续往下用没有算过的 `cost` 打印总价**。

## 八、循环

### 25. `while` 里用 `continue` 会死循环

```cpp
int i = 1;
while (i <= 5)
{
    if (i == 3) continue;      // 错：i 永远停在 3
    cout << i << " ";
    i++;                       // continue 把这行也跳过了
}
```

`i == 3` 时 `continue`，回到 `while (i <= 5)` 还是 3，永远出不来。

**`for` 为什么没事**：`for (...; ...; i++)` 的 `i++` 写在循环体**外面**，`continue` 跳不到它。

**结论**：`while` 里用 `continue`，一定要保证更新语句在 `continue` **之前**执行过。

### 26. `break` 只能跳出一层

```cpp
for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 5; j++)
    {
        if (j == 3) break;     // 只跳出内层 j
        cout << "i=" << i << " j=" << j << "\n";
    }
}
```

输出是 `i=1 j=1`、`i=1 j=2`、`i=2 j=1`……**外层照样跑满 3 圈。**

想跳出两层要用**标志变量**：

```cpp
bool stop = false;
for (int i = 1; i <= 3 && !stop; i++)     // 条件里加 !stop
{
    for (int j = 1; j <= 5; j++)
    {
        if (j == 3) { stop = true; break; }   // 先竖旗，再跳出内层
    }
}
```

### 27. 阶乘的循环变量要从 1 开始

```cpp
int fact = 1;
for (int i = 0; i <= n; i++)
{
    fact = fact * i;           // i=0 时 fact = 1 * 0 = 0
}
```

**现象**：结果永远是 0。

**原因**：第一圈 `fact` 就被乘成 0，之后一路乘 0 还是 0。

**正确**：`for (int i = 1; i <= n; i++)`。

**教训**：累乘的初值是 1，累加的初值是 0，循环起点是 1 还是 0 要看题目。

### 28. `for` 后面多一个分号 = 空循环体

```cpp
for (int i = 1; i <= 5; i++);   // 分号就是循环体，什么也不做
```

这行能编译，但循环体是那个空分号，后面的大括号跟循环就没关系了。

## 九、类型与输出格式

### 29. 整数除法会丢掉小数

```cpp
average = digit_sum / 3;       // 472 三位和的平均值算成 4
average = digit_sum / 3.0;     // 正确：4.33
```

**原因**：两个 `int` 相除，结果还是 `int`，小数部分直接砍掉。要得到小数，**至少有一边得是浮点数**。

同理：`double zhanbi = miao / 3600 / 24;` 如果 `miao` 是 `int`，前面全是整数除法，最后才转成 `double`，小数早就丢了。

**写法**：`(double)miao / 3600 / 24` 或 `miao / 3600.0 / 24`。

### 30. `setprecision(1)` 一定要配 `fixed`

```cpp
cout << setprecision(1) << 607.111;              // 输出 6e+02
cout << fixed << setprecision(1) << 607.111;     // 输出 607.1
```

**原因**：`setprecision` 单独使用时是「**有效数字**位数」，配 `fixed` 之后才是「**小数点后**位数」。

**而且 `fixed` 一旦设置就一直有效**，写在 `cout` 上不用每行都写；重复写虽然是冗余的，但不会错。

### 31. `(int)` 是截断，不是四舍五入

```cpp
(int)3.9   →  3
(int)-3.9  →  -3
(int)2.56  →  2
(int)-2.56 →  -2
```

**注意负数**：`-3.9` 变成 `-3`，是往 0 的方向砍，不是往下取整。要四舍五入用 `round()`。

## 十、条件运算符 `?:`

### 32. 三个部分一个都不能少

```cpp
int m = a > b ? a;              // 错：少了冒号
int m = a > b ? a : b;          // 对
```

**编译器**：`error C2059: 语法错误:";"`

### 33. `?:` 和 `<<` 混用要加括号

```cpp
cout << a > b ? a : b << endl;              // 错
cout << (a > b ? a : b) << endl;            // 对
```

**编译器**：`error C2678: 二进制">": 没有找到接受"std::basic_ostream<...>"类型的左操作数的运算符`

**原因**：`<<` 的优先级比 `>`、`?:` 都高，这行被解析成 `(cout << a) > b ? a : (b << endl)`。**`cout << a` 返回的是 `cout` 本身，`cout > b` 根本不存在。**

**规律**：只要把三元运算符塞进 `cout`，就老老实实加一对括号。

## 十二、还没搞明白的（先记下来）
